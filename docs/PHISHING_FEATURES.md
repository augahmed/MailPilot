# Local phishing feature extraction

Implemented in [PhishingFeatureExtractor](../backend/internal/risk/features.go), with the structured [PhishingFeatures model](../backend/internal/domain/phishing.go). `NewPhishingFeatureExtractor().Extract(ctx, email)` accepts a normalized `domain.Email` and returns observations identified by account ID, email ID and extractor version `phishing-features-1`.

This is an extraction stage only. It does not assign a score, classify a message as phishing, establish safety, persist results, expose an IPC/UI operation or change a mailbox. It uses no LLM, embeddings, external threat intelligence, DNS lookup, link visit or attachment download/execution. A later scoring stage can consume these observations separately. No dependencies or migrations were added.

## Supported observations

| Signal                           | Representation and meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| From, Reply-To, Return-Path      | Lowercase ASCII IDNA domains, with arrays retaining distinct domains from ordered duplicate headers/address lists. A singular summary is populated only when parsing succeeded and exactly one distinct domain was observed. A present malformed From never falls back to the normalized sender. If From is absent, sender fallback is marked `normalized_sender`. `<>` is a null Return-Path, not a failed parse or authentication failure.                                     |
| Authentication-Results           | Retains bounded unfolded raw data, header index/name, authserv-id/version, parsed method/version/result, reason and typed properties, plus malformed/no-results flags. Handles common RFC 8601 clauses, folding, quoted values/escapes and nested comments. It is a bounded parser, not a complete RFC grammar validator.                                                                                                                                                        |
| SPF, DKIM, DMARC                 | Summarizes recognized results from successfully parsed Authentication-Results; SPF also accepts Received-SPF. Missing/unusable evidence is `unknown`; differing reported results are `conflicting`. Arrays retain distinct recognized claims. Future header/method versions and unknown result words are preserved as data but excluded from summaries and reported as limitations. DKIM-Signature presence does not establish a DKIM pass.                                      |
| URLs and domains                 | Counts observed HTTP(S) and protocol-relative references in subject/plain text and HTML `href`, `src`, `action`, `formaction`, `poster`, `background`, plus URL-like HTML text outside anchors. Plain text recognizes `http://`, `https://` and `www.` references. Domains are normalized; per-reference source and registrable domain are retained. Paths, query values and user information are omitted from returned URL data.                                                |
| Visible-link mismatch            | An anchor whose entire text resembles a domain/web URL is compared to its destination domain. Inline markup and HTML entities are decoded. `VisibleLinkMismatch` reports differing exact normalized hosts; `CrossSiteMismatch` additionally compares registrable domains using the public suffix list. Descriptive text such as “View receipt” supplies no domain evidence. No brand inference occurs.                                                                           |
| IP-address URLs                  | Canonical IPv4 and IPv6 literals, including hosts that normalize to IPs through IDNA. Historical browser-specific numeric/hexadecimal IPv4 spellings are not resolved.                                                                                                                                                                                                                                                                                                           |
| Punycode                         | Flags normalized `xn--` labels from Unicode or existing ASCII IDNs; aggregate domains include address headers and URL destinations. This does not identify mixed scripts or prove impersonation.                                                                                                                                                                                                                                                                                 |
| URL structures                   | `embedded_credentials`, `non_default_port`, `many_subdomains` (at least six labels), `long_hostname` (over 80 bytes), `backslash`, `encoded_delimiters` (`%2f`, `%5c`, `%40`, `%3a`), `double_encoding` (`%25`) and `external_redirect_target`. Redirect observations inspect absolute web targets in centralized query keys, decoded once; they retain target domains only and never follow redirects. These traits also occur in legitimate links.                             |
| Executable attachment extensions | Centralized binary/installer/script/shortcut suffixes in [attachments.go](../backend/internal/risk/attachments.go), matched without case sensitivity after either path separator and trailing Windows spaces/dots. Records attachment index, bounded filename, extension and a double-extension flag. Final suffix matters: `notice.exe.txt`, PDF and ZIP files are not marked executable. No file bytes, MIME-type verification, archive inspection or malware analysis occurs. |
| HTML forms                       | Counts opening form tokens outside discarded elements; form/action URLs are observed separately. No form is submitted, rendered or executed. This is token evidence, not browser DOM validation.                                                                                                                                                                                                                                                                                 |
| Language                         | Centralized English phrases in [language.go](../backend/internal/risk/language.go) for urgency, account security and credentials. Case, whitespace and hyphens are normalized with whole-word boundaries. Returns matched phrase/kind/source once per phrase and source, without excerpts. Negation, intent and other languages are not interpreted. Legitimate password-reset/security messages can match.                                                                      |

All authentication observations have `Provenance = unverified_header`, including headers claiming a familiar authserv-id. The Gmail adapter currently does not establish a trusted Authentication-Results boundary. These claims must not be treated as verified passes or failures. Header absence never means authentication failed. See [RFC 8601](https://www.rfc-editor.org/rfc/rfc8601.html) for authentication assertion provenance.

`URLCount` counts references, including duplicates across alternative plain/HTML bodies and malformed web references. `UniqueURLCount` deduplicates parsed targets in memory after normalizing scheme/host; it does not follow redirects or equate all browser URL spellings. `URLDomains` deduplicates usable destinations. Relative references and non-web schemes (including mailto/javascript/data) have separate counts/observations and are not resolved against a base URL. Malformed web references count but yield no destination domain.

HTML is tokenized locally with the existing pinned [x/net/html](https://pkg.go.dev/golang.org/x/net/html) dependency; [IDNA](https://pkg.go.dev/golang.org/x/net/idna) and the public suffix list use the same existing x/net module. Script, style, head, template, iframe and object content is discarded. The tokenizer keeps the first duplicate attribute. CSS visibility, DOM recovery, script-generated links, image text, `srcset` and CSS URLs are not interpreted. A cache containing plain text derived from HTML can repeat displayed link text as a plain-text reference; sources remain distinct, and counts are observations rather than counts of unique clickable links.

## Defensive limits and partial evidence

The extractor has fixed limits: 2,000 headers; 8 KiB per relevant header; 128 KiB total header values; 16 KiB subject; 1 MiB each plain/HTML body; 64 KiB HTML token; 64 discarded-element nesting levels; 500 total web/relative/non-web references; 4 KiB per URL or anchor text; 200 attachment metadata entries; 1 KiB filename; 256 distinct issues plus one overflow marker. Authentication parsing also limits comment nesting, token count, clauses and properties.

Invalid UTF-8 is repaired for text inspection. Oversized text is truncated and marked incomplete; oversized headers, URLs and filenames are not interpreted as complete evidence. Malformed address headers suppress singular domain summaries; malformed authentication headers never contribute to result summaries. Valid partial observations elsewhere survive. Resource limits, unsupported authentication evidence, malformed inputs and bodies not marked complete are reported through `Incomplete` and safe issue codes/source/index. These fields never contain parsing-error excerpts. HTML tolerates malformed markup; observed unclosed/nested anchors and token failures are reported, but the tokenizer does not diagnose every syntax error. Cancellation returns a context error without publishing a partial result. Other malformed message data yields partial observations rather than a panic.

Missing cached content or unsupported structures mean there may be unobserved signals. An empty feature list is never a safety guarantee. Returned raw headers, domains and attachment names remain sensitive untrusted mail data: do not log them or treat them as action instructions.

## Synthetic verification

[testdata](../backend/internal/risk/testdata) contains a legitimate receipt, a suspicious credential-themed message and a malformed message. All are synthetic; URLs use example domains and documentation IPs. [Tests](../backend/internal/risk/features_test.go) exercise duplicate/conflicting headers, folded/quoted/commented authentication data, forged authserv-id claims, IDNA/IPs, matching and deceptive links, redirects, forms, executable suffixes, benign security language, bounded inputs, cancellation, deterministic independent results and parser fuzzing. They do not contact a mailbox or a threat service.
