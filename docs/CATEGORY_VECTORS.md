# Local category representations

Implemented 2026-10-20. Categories have account-scoped derived prototypes in the
same SQLite database, generated by the existing `app.LocalIndex` coordinator and
packaged local MiniLM provider. Prototype generation itself does not classify, assign or label mail. The [shared semantic classifier](SEMANTIC_CLASSIFICATION.md) now consumes these prototypes after generation.
It does not call external AI, Gmail or the rule engine.

New accounts receive six enabled definitions: Jobs (applications and interviews),
School, Receipts, Finance, Newsletters and Personal. Migration 018 combines the two
old job defaults only when both are pristine and unused, with no account review or
action history. Edited, disabled, deleted or referenced legacy definitions and all
manual assignments remain intact. Reconnection does not reseed defaults.

## Generation and explanation

**Start indexing** or **Resume indexing** in Local Email Index explicitly builds
email vectors, then enabled category prototypes, then dependent local assessments. Opening categories, editing a
definition, confirming an example, startup and status polling never run inference.
Pause, Cancel, restart recovery and model failure use the existing coordinator.
Counts separately report enabled/ready/partial/pending categories; email embedding
counts continue to count only email chunks. Ordinary categories work without a model.

For each definition, the shared `mail.Chunker` treats the name as subject and the
natural-language description as body, using the same pinned WordPiece tokenizer,
256-token input limit, 32-token overlap and exact `mail.ModelInput` recipe as mail.
All definition parts are embedded locally without silent truncation. Their unit
vectors are averaged and normalized into a definition centroid.

Examples are optional and require a separate **Choose a confirmed example** →
**Preview** → **Confirm this email** action in the category representation panel.
A confirmation binds the current reader/source revision, account and category.
Existing assignments and model/rule predictions never become examples. Up to ten
emails may be confirmed per category. Removing an example affects only its use in
the representation, not the email or its assignments.

Each confirmed email contributes up to three current compatible, complete shared
chunk vectors, ordered by authored, forwarded, quoted, subject, then other sections,
with chunk order/ID ties. Equal content and overlapping passages within the same
source section are deduplicated. Normalize the mean of these vectors into one
email centroid. The final unit prototype is the normalized equal-weight mean of
the definition centroid and each included email centroid. A long email therefore
has the same aggregate weight as a short example. No example email is re-embedded
for categories and no example vectors are copied to another table.

The panel shows the exact definition model inputs, model/version, current status,
confirmed source revisions, selected chunk IDs, subject/section context and labeled
passage excerpts. **Open original example** opens the revision-bound cached reader
with that evidence. Excerpts may be shorter than the embedded chunks; the shared
chunk records retain the complete passages and context. No remote content loads.

Without examples, the definition centroid is the ready prototype. Changed source
text is excluded until explicitly reconfirmed. Missing/incomplete/incompatible
example vectors are excluded until the shared index is ready. A prototype built
with any excluded example is `partial`; the definition remains usable. A later
index/source change invalidates it and the next explicit run regenerates it.

Recipe identity: `category-prototype-v1-definition-and-examples-equal-unit-mean`.
These vectors are representations, not predictions or calibrated probabilities.

## Persistence and invalidation

Migration [018](../backend/internal/store/sqlite/migrations/018_category_prototypes.sql)
adds `category_examples` and `category_prototypes`, composite account/category/email
foreign keys, category edit nonces and a category recipe on the existing index job.
Historical vector tables remain inert. Prototypes are keyed by account, category
and profile hash, containing model ID/version/dimension/fingerprint, preprocessing
and chunk versions, recipe, definition/source hashes, definition inputs, cached
definition centroid, final vector and status. Old model profiles remain separate.

Category name/description/enabled edits, explicit confirmation changes, source
changes, shared index generations, vector updates, tombstones and purge atomically
invalidate affected final vectors. Description edits never overwrite manual fields.
A cached definition centroid survives example-only changes. Definition changes or
model/preprocessing changes require compatible inference. Changed model artifacts
cannot reuse the same registered model version.

Inference happens outside transactions. Publication rechecks the authorized run
and its generation, current category edit nonce, exact confirmation identities,
source revisions and selected chunk/vector generations. Edits reverting to the same
text, remove/reconfirm cycles, pause, restart and purge cannot revive stale workers.
Source removal cascades confirmations and clears the derived final vector; it does
not erase immutable action journals or imply forensic deletion.

`categories.vectors` / Tauri `category_vectors` provides only inspect, explicit
confirm and remove operations. It accepts no raw text, vector, provider, model,
path, SQL or classification operation. See [IPC contract](../contracts/README.md).

## Verification

Synthetic Go tests cover definition-only categories, cache replay, equal-weight
centroids, edits and edit reversion, explicit examples, ignored predictions/manual
assignments, incomplete/source-changed examples, shared vector reuse, model and
preprocessing changes, account isolation, composite foreign keys, limits, cancellation,
purge, stale workers and migration preservation. Frontend/Rust/Go share a strict
fixture. UI tests exercise preview-before-confirmation and late-response clearing.

`npm run test:categories:native` builds a synthetic native test in the fixed packaged
resource layout, with strict CGO checks and network access denied. It verifies six
384-dimensional unit prototypes and zero new inference for an example-only update.
Its generated report is local under `.cache/category-vector-qualification.json`.
No weights, native libraries, databases or qualification build outputs are committed.
